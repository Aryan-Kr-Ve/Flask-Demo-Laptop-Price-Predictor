What's under the hinge

This tool wraps a regression model trained on real retail laptop listings. Give it a configuration, it gives back a price — here's how that price gets made.

The dataset

1,302 laptop listings, each with brand, form factor, CPU and GPU family, RAM, storage split across HDD and SSD, screen size and resolution, touchscreen and IPS flags, operating system, weight, and price. Screen size and resolution are combined into pixels-per-inch during preprocessing, since that's the feature that actually correlates with price — a 13″ 4K panel and a 17″ 4K panel are not the same display.

The models

Ten regressors were benchmarked against the same features: linear, ridge and lasso regression, k-nearest neighbours, decision tree, random forest, extra trees, AdaBoost, gradient boosting and XGBoost. A voting/stacking ensemble of the strongest performers came out on top and is what runs behind this page, reaching roughly 89% R² on held-out listings. Price is modelled on a log scale and exponentiated back to rupees after prediction — prices don't move linearly with specs, so the model doesn't either.

This interface

The original project shipped as a Streamlit script. This front end wraps the same pickled pipeline in a small Flask app: pages are rendered server-side, and the configurator on the Predict page calls a JSON endpoint — POST /api/predict — that returns a price without a page reload. Dropdown values come from GET /api/options, sourced from the same dataframe the model was trained on, so the form can never offer a brand or CPU the model hasn't seen.

Reading a result

Treat the number as a market estimate, not a quote. The model has never seen a live price feed — it's pattern-matching against listings that may be a few years old, so absolute prices drift even where the relative ranking between configurations stays sensible. A useful way to use it: hold most fields fixed and change one — say, RAM — to see how much of the price that one spec is actually carrying.
